# 武术量化考核评分标准查询

依据《武术量化考核评分标准（中期考核试行版）》2026.9 制表整理的可搜索查询网站。评分数值、档位文字、扣分项均与原表逐条一致。

## 使用

直接用浏览器打开 `index.html` 即可，无需服务器与网络。若要分享给他人，把整个 `wushu-standards` 文件夹放到任意静态托管（校内服务器、GitHub Pages、对象存储等）即可。

## 单文件 exe（推荐给不熟悉电脑的人）

`武术考核标准查询.exe`（约 39 MB）已经把整个网站、**骨架模型**、以及**公网隧道程序**都嵌进去了：

- 双击运行 → 本机自动起一个只读服务 → **同时开一条 Cloudflare 公网隧道** → 窗口里直接给出一个
  `https://xxx.trycloudflare.com` 的手机访问地址；把这个地址发给任何人，**手机在任何网络下都能打开**，不要求同一个 WiFi；
- 系统默认浏览器同时打开本机页面；
- **不需要联网、不需要安装任何东西**（只用 Windows 自带的 .NET Framework 4.x，Win10/11 都有）；
- 关掉那个小窗口，本地服务和隧道一起停止；
- 可以复制到 U 盘、发给别人、放在任意目录运行，不依赖同目录的任何文件。

因为内置的是你自己的 Edge/Chrome，所以视频考核、摄像头实时分析都能用（`127.0.0.1` 属于浏览器的安全上下文）。

> 首次运行 Windows 可能弹「已保护你的电脑」——因为 exe 没有代码签名。点「更多信息」→「仍要运行」即可。

### 手机访问的三条通道

| 通道 | 适用范围 | 说明 |
| --- | --- | --- |
| 公网地址（窗口第一栏）+ 二维码 | 任何网络 | 走 Cloudflare 隧道，手机在 4G/5G/任意 WiFi 都能开；点「显示二维码」让队员直接扫码 |
| 局域网地址（窗口第二栏） | 同一 WiFi | 隧道不通时的备用；手机上**上传视频做考核**可用，摄像头实时分析在 http 下不可用 |
| 本机地址 | 只在这台电脑 | 调试用 |

**注意：exe 本身只能在 Windows 电脑上运行，手机装不了。** 手机要用的是窗口里给出的**网址或二维码**，不是 exe 文件。网页本身已经做了手机适配（窄屏单列、触屏按钮），手机打开就是完整功能。

「显示二维码」会在本机浏览器打开 `qr.html`，把当前公网地址画成二维码——投屏或拿手机扫一下就能打开，不用发文件、不用输网址。这个页面也随网站一起发布，例如托管后可访问 `.../qr.html?u=https://你的网址/`。

### 装到手机桌面（以后点一下就用）

网站支持 PWA，可以像 App 一样装到手机桌面上：

1. **第一次**：手机打开网址（扫码或输网址），页面底部会出现"添加到主屏幕"的提示条。
   安卓点「添加」，iOS 点浏览器分享按钮 →「添加到主屏幕」。
2. **以后**：点桌面上的「武术考核」图标直接打开，全屏、没有地址栏，不用再扫码或输网址。
3. **离线可用**：`sw.js` 会把页面、脚本和 9 MB 的骨架模型缓存到手机本地。实测把服务端完全关掉之后，页面和全部 17 项规范照常打开；骨架模型在第一次用过视频考核后同样会进缓存。

一个前提：图标指向的是当时那个网址。**隧道地址每次重启都会变**，变了就要重新添加一次。把网站放到正式托管上、地址固定之后，就一次装好永久有效。

公网地址的两个已知限制，必须知道：**关掉窗口就失效**，而且**每次重新打开都会换一个新的地址**。要做到"永久不变、电脑关机也能用"，只能把网站放到正式托管（见 `发布说明（给教练）.md`）。

手机端用公网地址时可以完整使用全部功能：看规范、查动作、上传录像做自动评分（模型走隧道下载一次约 20 MB，之后有浏览器缓存）。手机上"摄像头实时"需要 https —— 公网地址正是 https，所以也能用。

exe 的源码在 `app-exe/`：`Program.cs` 是用 `TcpListener` 实现的极简静态服务器 + WinForms 窗口 + 隧道管理，`build-exe.ps1` 负责生成图标、嵌入资源（含 gzip 压缩的 cloudflared）、调用系统自带的 `csc.exe` 编译。改完网站内容后重新运行该脚本即可重新打包。

可选的调试参数：`--no-open`（不自动开浏览器）、`--write-url=路径`（把网址写到文件）、`--port=N`（指定端口，被系统预留端口占用时会自动退回随机端口）。

## 功能

- **全部规范**：按腿法、跳跃、套路演练、平时分分组展示全部 17 项考核内容，含 10/8/6/4 分档标准、扣分内容、次数要求。支持关键字筛选与分类筛选。
- **按动作查询**：输入动作名称直接调出对应规范；支持部分名称（如“踢腿”）、拼音首字母（如 `tkfj`）；名称不匹配时自动转到标准正文全文检索。
- **视频考核**：上传动作视频或开摄像头实时拍摄，自动提取骨架，按文档分档标准判档、核对扣分项、给出预估得分，并支持用教练示范视频标定阈值。
- **打印**：一键打印或导出 PDF，打印样式自动隐藏交互控件并展开全部卡片。
- **深链接**：`#/lookup/旋风脚` 形式的链接可直接定位到某个动作。

## 视频考核

### 原理

用 MediaPipe PoseLandmarker 逐帧提取 33 点骨架，再把骨架换算成**以身体为参照**的量，因此不受拍摄距离和画面构图影响：

- 以髋中点为原点、躯干长度为 1、身体朝上的方向为正，表达所有高度（髋 = 0，肩 = 1）；
- 文档里的「跟过头顶 / 过下巴 / 脚尖过肩」本身就是几何判据，直接按实测高度判档；
- 「超过 450° / 360° / 270°」按髋轴累计转体角判定；
- 「两腿幅度超 135°」按两腿在髋部的夹角判定。

界面会把头顶线、额头线、下巴线、肩线直接画在画面上，肉眼就能核对判定是否合理。

### 分数是怎么算出来的

1. **档位**：按文档分档文字从上往下比对，命中哪一档就是哪一档的基础分。
2. **扣分项**：逐条自动核对。「每项 1 分，不累计扣分」按文档原意，只要有一项不达标就扣 1 分。
3. **最终**：档位分 − 扣分。

把握较低的自动判定（如手臂弯曲）只提示、不扣分，标记为「需人工确认」。掌型、击响、落地位移这类无法从骨架判断的项，一律交由教练复核。

### 标定（重要）

文档给了数值的判据（高度、角度、转体）不需要标定。文档没给数值的判据——「抡腿明显」「爆发力强」「节奏分明」「晃动」——需要标定：

1. 让教练录一段该动作的满分示范；
2. 选择动作 → 导入示范视频 → 开始分析；
3. 点「把这次结果设为该动作的 10 分参考」；
4. 之后所有被考核视频都按这份档案判定，可在「标定档案」里逐项微调阈值。

标定值存在浏览器 localStorage 里，换浏览器或换设备需要重新标定。

### 运行要求

- **文件夹版**：需要能访问 `assets/pose/`（约 20 MB），建议用 http(s) 打开，例如本地起服务或部署到静态托管。
- **单文件版**：没有本地模型，会自动改用 CDN 载入模型，**需要联网**。
- 摄像头实时分析需要 `https` 或 `localhost`（浏览器的安全限制）。

### 各动作支持情况

| 动作 | 自动判定依据 |
| --- | --- |
| 正踢腿 / 侧踢腿 | 脚跟最高点 vs 额头线 / 下巴线，脚尖 vs 肩线 |
| 里合腿 / 外摆腿 | 同上 + 抡腿幅度 |
| 后扫腿 | 身体累计转体角 360° / 180° |
| 腾空飞脚 | 击响时脚尖高度 |
| 外摆莲 / 旋风脚 | 累计转体角 450° / 360° / 270° + 腾空 |
| 旋子 | 腾空高度 |
| 腾空正踢腿 | 两腿幅度 135° + 脚跟高度 |
| 侧手翻 | 倒立时长占比（把握较低，建议以人工评定为准） |
| 单拍脚+翻身拍地、套路演练、平时分 | 暂不自动评分，需人工评定 |

### 已知限制

单目视频的骨架估计有固有误差：机位越接近正侧或正前、人越完整入镜、画面越清晰，结果越稳。侧视角下模型偶尔会把左右腿标反，程序已做容错（按离地高度判断支撑腿），但极端姿态下指标仍可能偏离。**自动评分适合做日常训练反馈与粗筛，最终考核成绩请以教练人工评定为准。**

## 一次考核的完整流程

### 第 0 步：标定（每个动作做一次）

1. 让教练按满分标准录一段示范：正侧机位，全身入镜。
2. 打开「视频考核」→ 选动作 → 被考核人填「示范-王教练」→ 导入示范视频 → 开始分析。
3. 点「把这次结果设为该动作的 10 分参考」。
4. 重复到所有要考的动作都标定完。
5. 点「导出标定文件」存好这个 JSON。换电脑、换浏览器、或把标准给别的教练时，点「导入标定文件」即可。

文档里已经给了数值的判据（高度、角度、转体）不必标定；标定主要影响「抡腿明显」「节奏」「晃动」这类没有数值的判据。

### 第 1 步：拍摄（决定准确度的一步）

- 机位取正侧方或正前方，离人 4–6 米，手机横屏并固定住。
- 人全身入镜，**头顶和脚下都要留出空间**——踢腿时脚会出画，出画就测不到。
- 画面里只留一个被考核者，旁边的人离镜头更近会干扰识别。
- 光线均匀，背景尽量干净。
- 一段视频只拍一个人、一个动作的一组次数。

### 第 2 步：逐个考核

1. 「被考核人」填姓名或学号，选动作，导入视频（或点「摄像头实时」直接拍）。
2. 「分析精度」用默认的**快速**即可；如果结果里提示帧数偏少，程序会自动改用逐帧精析。
3. 点「开始分析」，等进度跑完。
4. 看结论：判定档位、扣分项逐条核对、预估得分、次数统计。
5. 点「记入成绩表」。

### 第 3 步：导出成绩

全部考完后在成绩表里点「导出 CSV」，Excel 或 WPS 可直接打开；也可以「导出 JSON」做备份。成绩表存在浏览器本地，换电脑前先导出。

## 文件

- `index.html` — 页面结构
- `assets/styles.css` — 样式
- `assets/data.js` — 考核标准数据（唯一数据源，改这里即可更新内容）
- `assets/app.js` — 搜索、筛选、渲染逻辑
- `assets/video.js` — 视频考核的指标计算与判定规则
- `assets/video-run.js` — 视频考核的界面与骨架提取流程
- `assets/pose/` — MediaPipe 运行时与姿态模型（约 20 MB）
- `build-single.mjs` — 打包单文件版

## 更新数据

编辑 `assets/data.js` 中的 `actions` 数组即可。每个动作的字段：

| 字段 | 说明 |
| --- | --- |
| `name` | 表中原名，显示与搜索均用它 |
| `shortName` | 可选，卡片标题的短名（如“外摆莲”） |
| `category` | `leg` 腿法 / `jump` 跳跃 / `routine` 套路演练 / `daily` 平时分 |
| `score` | 满分 |
| `reps` | 次数要求 |
| `alias` | 搜索别名，含拼音与简称 |
| `levels` | `[{score, points:[...]}]`，对应 10/8/6/4 分标准 |
| `deduct` | `{rule, items:[...]}` 扣分内容及扣分规则 |
| `note` | 备注 |
